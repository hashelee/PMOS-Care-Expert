# PMOS-Care-Expert

**PMOS Care Expert: An Explainable Missing-Information-Robust Framework for PMOS Risk Stratification
Integrating Automated Ovarian Follicle Quantification with Clinical and Biochemical Risk Modelling**

Final-year project, University of Westminster.

## Repository structure

```
PMOS-Care-Expert/
├── data/
│   ├── raw/            # original downloads, never edited, not committed (see data/raw/README.md)
│   └── processed/      # generated by code, not committed
├── docs/               # data dictionary, feature groups, weekly notes
├── notebooks/          # numbered notebooks, run in order
├── results/            # metrics, tables and figures produced by code (committed as evidence)
│   └── audit/
├── src/                # reusable Python code imported by the notebooks
│   ├── config.py           paths, random seed (42), constants
│   ├── feature_groups.py   feature dictionary: groups, acquisition type, plausibility bounds
│   ├── data_loading.py     load + rename + type-fix the dataset (every fix logged)
│   └── audit.py            dataset audit (IMP-02 to IMP-05)
├── requirements.txt
└── README.md
```

## Setup (Windows)

```bat
cd PMOS-Care-Expert
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Then download the dataset as described in [`data/raw/README.md`](data/raw/README.md).

## Running

| Step | Tracker tasks | How to run | Main output |
|---|---|---|---|
| 1. Dataset audit | IMP-02, 03, 04, 05 | `notebooks/01_dataset_audit.ipynb` or `python -m src.audit` | `results/audit/audit_summary.md` |

Every notebook is run from the `notebooks/` folder; every script from the repository root.

## Reproducibility rules

- One random seed (`SEED = 42` in `src/config.py`) for every split, model and resampling step.
- Raw data is never edited. All cleaning is done in code and logged.
- No rows are removed and nothing is imputed during the audit. Imputation, scaling and any
  outlier handling happen inside the cross-validation pipeline so test folds never leak into training.
- Commit after every working step; the commit history is the evidence for the progress tracker.
